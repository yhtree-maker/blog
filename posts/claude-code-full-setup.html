Claude Code 完全配置指南：Skills、Obsidian 与博客发布

2026-07-25

前言

这套配置让我可以在手机上完成从采访笔记到博客发布的完整写作流程。用几个词概括：Obisidian 记录，Claude Code 写作，一键发布，网盘备份。

本文记录完整的搭建过程，涵盖三个方向：

  1. 安装 Claude Code Skills（浏览器自动化、人性化写作、头脑风暴等）
  2. 打通 Obsidian 与 Claude Code 的文件系统
  3. 搭建静态博客发布管道

一、安装 Claude Code Skills

Skills 是 Claude Code 的可复用技能系统，能将常用工作流固化为命令。

已安装的技能清单

| 技能 | 功能 | 用法 |

|------|------|------|

| find-skills | 自动搜索和推荐技能 | 直接说"帮我找一个…的技能" |

| humanizer-zh | 识别 24 种 AI 写作痕迹并人性化改写 | /humanizer-zh |

| brainstorming | 九步强制创意规划流程 | /brainstorming |

| web-access | 通过 CDP 直连 Chrome，处理需要登录的场景 | /web-access |

| agent-browser | 浏览器自动化（抓取/测试/表单/调试） | /agent-browser |

| skill-creator | 引导式创建自定义技能 | /skill-creator |

安装方式

由于 npm 环境存在 glob 模块损坏的问题，我采用了直接克隆仓库 + 手动部署的方式：

# 通用安装模式
git clone <repo-url> /tmp/<skill-name>
mkdir -p ~/.claude/skills/<skill-name>
cp SKILL.md ~/.claude/skills/<skill-name>/

所有技能文件存放在 ~/.claude/skills/ 目录下，Claude Code 会自动加载。

二、打通 Obsidian 与 Claude Code

核心原理

Android 上 Obsidian 运行在图形界面，Claude Code 运行在 PRoot Distro 命令行中。打通它们的关键是：不要试图让两个工具互相通信，而是让它们共享同一个文件系统。

PRoot Distro 容器可以直接访问 /storage/emulated/0/（Android 系统级挂载点，不会被容器隔离），所以只要将 Obsidian vault 建在共享存储路径下即可。

配置步骤

第一步：在 Obsidian 中创建 Vault

将 vault 位置设为：

/storage/emulated/0/Documents/obside/

第二步：在 PRoot Distro 中创建符号链接

ln -sf /storage/emulated/0/Documents/obside ~/obsidian-vault
ln -sf ~/obsidian-vault/articles ~/articles
mkdir -p ~/obsidian-vault/notes

第三步：验证连通性

echo "测试" > ~/articles/test.md
# 在 Obsidian 中应能看到 test.md
cat /storage/emulated/0/Documents/obside/articles/test.md
# 应输出 "测试"

最终目录映射

Obsidian (Android)                        PRoot Distro (命令行)
─────────────────                        ────────────────────
/storage/emulated/0/Documents/obside/    ~/obsidian-vault  (symlink)
  ├── .obsidian/                           ~/articles  (symlink)
  ├── articles/  ◄────────────────────── Claude Code 写文章
  └── notes/                              采访笔记存放

三、博客发布管道

技术架构

Markdown 文章 → publish.py (Python 标准库) → HTML → GitHub Pages
                    │
                    └── Jinja2 模板（内嵌 CSS，自包含）

全流程零外部依赖——publish.py 仅使用 Python 标准库，包含简易 Markdown 解析器、HTML 模板引擎和本地预览服务器。

文件结构

/root/blog/
├── publish.py          # 静态站点生成器
├── deploy.sh           # 构建 + Git 推送 + rclone 同步
├── all-in-one.sh       # 一键：构建 → 发布 → 备份
├── output/             # 生成的 HTML
└── worktree/           # GitHub Pages 仓库工作树

工作流

 1. Obsidian 记采访笔记         →  notes/
 2. Claude Code 读取并写文章    →  articles/draft.md
 3. Obsidian 中编辑草稿
 4. bash /root/blog/deploy.sh  →  发布到 GitHub Pages
 5. rclone sync                →  备份到网盘

常用命令

# 本地预览
python3 /root/blog/publish.py --serve

# 构建 + 发布
bash /root/blog/deploy.sh

# 一键：构建 + 发布 + 网盘备份
bash /root/blog/all-in-one.sh

四、权限配置

为减少 Claude Code 的审批弹窗，配置了 61 条权限规则：

  • 项目设置 (.claude/settings.json)：12 条通用规则，覆盖目录创建、符号链接、包管理、博客脚本、rclone 同步等
  • 本地设置 (.claude/settings.local.json)：49 条精确规则，覆盖具体操作路径

关键安全原则：

  • 博客脚本限定在 /root/blog/ 目录
  • 不开放任意代码执行（python3 和 node 已收紧为具体脚本路径）
  • WebFetch 开放所有域名（写作需要查阅资料）

五、补充工具

rclone 网盘同步

# 安装
curl -O https://downloads.rclone.org/rclone-current-linux-arm64.deb
dpkg -x rclone-current-linux-arm64.deb /tmp/rclone-extract
cp /tmp/rclone-extract/usr/bin/rclone /usr/local/bin/rclone

# 配置
rclone config

# 同步
rclone sync /storage/emulated/0/Documents/obside/ dropbox:obsidian-notes --progress

agent-browser CLI

npm install -g agent-browser
agent-browser install  # 下载 Chromium

小结

这套配置的核心价值：

  1. Skills 系统让 Claude Code 的能力模块化、可复用
  2. Obsidian 打通实现了移动端和命令行的无缝衔接
  3. 博客管道让写作到发布变成一步操作
  4. 权限配置大幅减少了交互摩擦

最终效果：掏出手机打开 Termux，输入 claude "帮我写一篇关于 XX 的文章"，Claude Code 读取笔记、生成草稿，在 Obsidian 中润色编辑，最后 bash /root/blog/deploy.sh 一键发布——全程无需切换设备。
